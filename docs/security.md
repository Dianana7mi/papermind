# Security and reliability boundaries

- Passwords: Argon2 via pwdlib; no plaintext password storage. JWT HS256 fixes algorithm/issuer/audience/expiry. Production requires a long secret and separate worker/PostgreSQL/Qdrant configuration.
- Ownership: private libraries are bound to the authenticated owner. API, graph tools, SQL filters, Qdrant filters and post-retrieval hydration all apply server scope. Files require authorization. Resource IDs are not access credentials.
- Input: strict Pydantic schemas, bound list sizes, parameterized SQLAlchemy statements, PDF MIME/extension/signature/page/encryption/size checks. Generated file paths never accept user paths. Body caps cover declared and streaming request lengths.
- Retrieval: source content remains untrusted. There is no arbitrary SQL, user URL fetch, shell or filesystem tool for the LLM. Tool names/arguments are constrained and server-owned user/library fields override model inputs. Public search calls one fixed OpenAlex endpoint; landing-page links are displayed only.
- Output: React escapes text; ReactMarkdown does not render raw HTML. No model key reaches the browser. Citations are SQL evidence IDs, not invented sequential model labels. Numeric result prose is rebuilt from checked fields. A separate LLM judge can assess textual entailment; this is explicitly weaker than deterministic verification.
- Browser auth: short-lived token in sessionStorage (tab lifetime). This does not protect against a successful same-origin XSS; avoid adding unsafe HTML renderers. Production CSP and HTTPS are configured. There is no refresh-token/session revocation service yet.
- Logout clears research/library/detail state and query cache. Session/epoch checks discard late private API/SSE/PDF responses after logout or scope switches; a browser regression checks a second account cannot see the first account's conversation.
- Limits: separate auth/API rate buckets, Redis in production, model request timeout/retry/context/input/total token bounds, configurable dollar cap when actual prices are supplied, graph tool/recursion/wall-clock caps, six-cell extraction batches and per-upload batch budget. Provider errors are not disguised as successful extraction.
- Failure recovery: atomic paper status claims prevent repeated worker processing. Celery uses late acknowledgements, bounded execution and worker-lost rejection. A scheduled recovery sweep marks expired processing jobs failed and redispatches pending jobs. SQL commits are authoritative; vector/file deletion is a durable cleanup outbox. No deletion of user data occurs in a migration.
- Paper status and processing Job/lease initialization commit in one transaction. The recovery sweep also repairs legacy processing papers which have no processing Job, so a crash between older split commits cannot permanently block retry/deletion.
- Unit checks derive from original cells/metric labels. A record-wide supported value never authorizes unverified experiment conditions. Per-field review is explicit, source-bound and audited; changing a reviewed value or its evidence invalidates that confirmation.
- Logging: request IDs, safe error types and timings; input bodies/private documents/secrets are not logged by application code. Third-party SDK verbosity is reduced. Opt-in Langfuse logs metadata/usage; do not enable prompt/content capture without a separate privacy decision.

Production ingress must remain Caddy-only. The API trusts forwarded headers only on the private Compose network, with no published backend port; Caddy overwrites `X-Forwarded-For`. Do not expose the API's forwarded-header configuration directly to the public Internet.

Verified tests cover owner isolation for libraries/papers/evidence/experiments/vectors, invalid uploads, schema injection, value/entity/citation errors, unit conversions, bounded graph failure, revision conflicts, idempotency and index deletion. This is not a penetration-test certificate or a high-concurrency benchmark. Public deployment and production integrations still need the checks in `deployment.md`.

Lexical cache keys include tenant/scope and a transactional SQL revision shared across replicas. Cached word statistics/IDs obey the corpus/LRU bounds; final source data is rehydrated through owner/library/ready-paper filters. Index building/query CPU work runs outside the event loop. Lexical capacity errors are explicit422; dense retrieval does not inherit that cap. Complete scientific-name boundaries preserve version/size/suffix distinctions. Unit selection prefers the addressed column, and ambiguous captions do not certify a unit.
